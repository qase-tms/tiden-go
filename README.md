# tiden-go

Go reporting for [Tiden](https://tiden.ai) — the continuous quality system.

## What's here

| Package | Purpose |
|---|---|
| `pkg/gotest` | `go test -json` (test2json) stream parser + the **stable case-identity rules** shared by every Tiden Go reporting surface |
| `tidenapi` | Generated Go client for the Tiden Public API (`https://api.tiden.ai`) — its own Go module, released independently. See [below](#tidenapi-generated-public-api-client). |

The primary consumer today is the `tiden` CLI's zero-touch wrapper:

```bash
tiden run exec -- go test ./...
```

It creates a Tiden test run, streams your suite's results into it, and
completes the run with the real verdict — no changes to your test code.

An in-process reporting library (`tiden.Test(t, ...)` with steps, params and
attachments) is the planned second phase and will live in this repository.

## Identity rules (the part you must not break)

- **Leaf subtest = case.** `TestLogin/expired_token` is its own repository
  case; `TestLogin` is only a container when it has subtests.
- **Signature** = `"<package import path>::<full test path>"` — param-free,
  case-sensitive, byte-stable across releases (golden-tested).
- **Suite path** = module-relative package path, one segment per element.
- Dynamic subtest names (`fmt.Sprintf` with counters, timestamps, random
  values) are an anti-pattern for reporting: Tiden's live documentation
  creates a permanent repository case per identity and never deletes on
  absence.

## `tidenapi`: generated Public API client

`tidenapi/` is a Go client for the [Tiden Public API](https://api.tiden.ai),
generated by [`openapi-generator`](https://openapi-generator.tech) from the
OpenAPI spec in [`qase-tms/tiden-specs`](https://github.com/qase-tms/tiden-specs)
(`public-api/v1/openapi.yaml`). It's a separate Go module
(`github.com/qase-tms/tiden-go/tidenapi`) so it can be versioned and released
independently of the root module.

Authentication is Bearer-token (an API token of the form `tfy_...`, created
in the app UI or via the CLI device-code flow):

```go
package main

import (
	"context"
	"fmt"

	tidenapi "github.com/qase-tms/tiden-go/tidenapi"
)

func main() {
	cfg := tidenapi.NewConfiguration() // defaults Servers to https://api.tiden.ai
	client := tidenapi.NewAPIClient(cfg)

	auth := context.WithValue(context.Background(), tidenapi.ContextAPIKeys,
		map[string]tidenapi.APIKey{
			"BearerAuth": {Prefix: "Bearer", Key: "tfy_..."},
		},
	)

	resp, _, err := client.WorkspaceServiceAPI.WorkspaceServiceListWorkspaces(auth).Execute()
	if err != nil {
		panic(err)
	}
	fmt.Println(resp)
}
```

See `tidenapi/README.md` for the full endpoint/model index and
`tidenapi/docs/` for per-operation examples.

**Rules:**

- **Generated code — never edit by hand.** Regeneration PRs arrive
  automatically from `qase-tms/tiden-specs` (its `sync-clients.yml`
  workflow, gated on the `CLIENTS_SYNC_TOKEN` repo secret) whenever the
  public API spec changes; review those like any other dependency bump.
- **Released independently** by tagging `tidenapi/vX.Y.Z` (the standard Go
  multi-module directory-prefixed tag convention) — the root module's tags
  are unprefixed (`vX.Y.Z`) and unaffected.

## Development

```bash
go test ./...
go vet ./...
gofmt -l .
```

Golden fixtures under `pkg/gotest/testdata/` are captured from real
`go test -json` runs — regenerate with `pkg/gotest/testdata/gen.sh`.

`tidenapi/` is generated and excluded from the root module's `go test`/`go
vet`/`gofmt` above (it's a separate module — see CI below for its own
checks).
